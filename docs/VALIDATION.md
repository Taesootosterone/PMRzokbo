## 별도 문서 프로그램 없이 PPTX + PDF 가져오기 — 2026-11-13, v1.3.2

기본 경로를 **PPTX의 구조·노트·정답 추출 + 함께 올린 PDF의 화면 변환**으로 바꿨습니다. LibreOffice 설치 확인 때문에 업로드를 막지 않습니다. PDF 경로는 외부 문서 프로그램을 호출하지 않으며, 서버에 기존 LibreOffice가 있는 경우에만 이전 자동 변환 방식을 선택할 수 있습니다. 원래 데이터 경로와 DB 스키마·백업 형식은 유지합니다.

- 단위 검사 **19개**, 프로덕션 빌드와 TypeScript 검사를 통과했습니다. 올바르지 않은 PDF와 진행 중인 작업의 교체 요청이 PPTX 원본·작업 상태를 덮어쓰지 않는 검사도 포함합니다.
- Chromium 브라우저 검사 2개에서 PPTX → PDF 대기 → 재접속 → PDF 업로드 → OCR/검토/초안 저장 → 등록/풀이를 확인했습니다. PDF는 검사 코드에서 직접 생성하며 LibreOffice를 사용해 만들지 않습니다. 외부 변환기 경로에는 호출 즉시 표식을 남기고 실패하는 프로그램을 연결했으며 **호출 표식이 만들어지지 않았습니다**.
- PPT 12장에 PDF 11페이지를 올리면 검토·등록으로 넘어가지 않고 두 장수를 알려 줍니다. 올바른 PDF로 교체하면 등록할 수 있습니다. 이전 버전처럼 화면 방식 필드가 없는 작업도 재분석 시 PDF 대기로 전환되고, 이미 등록한 두 문항은 유지되는 것을 확인했습니다.
- 실제 첨부된 **376장·63문항 원본**도 브라우저에서 PPTX와 PDF를 순서대로 업로드했습니다. 376장 전체를 새 PDF 경로로 읽어 정답 표시 52개·수동 확인 11개가 나왔고, 외부 변환기 호출은 없었습니다. **PDF는 앞선 v1.3.1 검사에서 이미 만들어 둔 동일 원본의 PDF를 재사용했습니다.** 이번 검사에서 PowerPoint/Keynote의 Mac PDF 내보내기를 실행한 것은 아닙니다.
- 해당 실제 자료의 2번·16번을 별도 테스트 DB에 등록해 문제 확대 그림·풀이·해설을 확인했습니다. 전체 백업을 새 경로에 복원해 두 문항·출처·연결, 네 이미지의 SHA-256, 풀이 기록이 보존됐습니다. 재등록은 추가 0·기존 2개 유지였습니다. 사용자 Mac과 PMRtest/NOAH 데이터는 변경하지 않았습니다.

**검증 경계:** 실제 PowerPoint/Keynote의 PDF 저장 메뉴와 Safari는 Mac에서 확인하지 못했습니다. 장수가 같은 다른 PDF나 바뀐 순서까지 자동 식별하는 기능은 없으므로 원래 PPT에서 같은 순서로 저장하고 미리보기를 대조해야 합니다. 원본 PPTX·PDF와 미등록 분석 캐시는 전체 `.pmrz` 백업에 포함되지 않습니다. 등록한 문항·이미지·기록·연결은 포함됩니다.

## PPTX만 업로드 → 내장 PDF 생성·저장 → 분석 — 2026-11-14, v1.4.0

기본 경로에 내장 변환기를 추가했습니다. `pptxtojson`으로 화면 요소를 읽고 내장 Skia 캔버스와 PDFKit으로 이미지 기반 PDF를 스트리밍 저장합니다. 한글 글꼴은 OFL 1.1의 Noto Sans KR를 앱에 포함했으며 글꼴 설치나 실행 중 다운로드를 하지 않습니다. 사용자에게 PDF 내보내기를 맡기거나 LibreOffice를 호출하는 기본 경로가 아닙니다. 수동 PDF와 이미 설치된 LibreOffice는 선택 기능으로 유지합니다.

- `npm test` **24개 통과**, 프로덕션 빌드와 TypeScript 검사 통과. 한글·형광펜이 있는 실제 생성 PDF의 페이지 수와 픽셀, 표 배경색, 이미지 전용 슬라이드의 원래 순서를 검사했습니다. ZIP 파일명과 표시 순서가 다른 경우도 정상입니다.
- 변환 중 취소하면 부분 PDF를 제거하고 원본을 유지하는 검사, 차트와 병합 표를 거부해 불완전한 PDF를 성공으로 내보내지 않는 검사를 통과했습니다. 원본 PPTX의 해시는 변환 전후 동일했습니다.
- Chromium 검사 **2개 통과**. 기본 PPTX 단독 업로드 → PDF 자동 생성 → **실제 브라우저 PDF 다운로드** → 12페이지 확인 → 문항 등록·풀이를 검사했습니다. 기존 33MiB 초과 파일의 수동 PDF/OCR/초안 저장 경로, 잘못된 PDF 장수 교체, 이전 작업 재분석, **보존한 PPT로 PDF 자동 생성** 전환도 확인했습니다. 외부 문서 변환기를 호출하면 실패하는 프로그램을 연결해 두었으며 호출 표식은 생성되지 않았습니다.
- 실제 첨부된 **31,380,050바이트·376장·63문항 PPTX만** 브라우저로 업로드했습니다. PDF를 추가하지 않고 **376페이지·104,690,030바이트 PDF**를 생성·저장·다운로드했으며, 파일 SHA-256은 서버 기록과 일치했습니다. 앞선 PDF를 재사용한 v1.3.2 검사와 달리 이번에는 PPTX에서 새 PDF를 만들었습니다.
- 생성한 PDF로 376장 전체를 후속 처리해 정답 표기 52개·수동 확인 11개가 나왔습니다. 이미지 기반 PDF에서 문항을 새로 추정한 것이 아니라 PPTX의 번호·역할·노트·형광펜 정보를 함께 사용합니다. 의료적 정답 정확도를 검증한 비율은 아닙니다.
- 실제 자료의 2번·16번을 격리된 DB에 등록해 확대 문제 자료·풀이·해설을 확인했습니다. 전체 백업을 새 경로에 복원해 두 문항·연결·네 이미지의 SHA-256·풀이 기록을 대조했습니다. 재등록은 추가 0·기존 2개 유지였습니다.
- 서버를 정상 종료하고 같은 데이터 경로로 다시 시작했습니다. 자동 생성 PDF의 파일 시각·SHA-256과 다운로드 응답, 두 문항·한 번의 풀이 기록이 유지됐습니다. 원본 파일도 변경되지 않았습니다. PDF와 원본·분석 자료는 코드 밖의 데이터 경로에 저장합니다.
- 실제 자료의 일부 페이지를 열어 한글 지문·사진 두 장·형광펜 표시가 남고 지문이 사진과 겹치지 않는 것을 시각적으로 확인했습니다. 사용자의 원본과 실제 문제 이미지는 GitHub에 포함하지 않았으며 회귀 자료는 직접 만든 데모입니다.

**검증 경계:** 내장 변환은 PowerPoint 전체 기능의 동일 구현이 아닙니다. 차트·SmartArt·수식·OLE·동영상·그룹 도형·병합 표 등의 미지원 항목은 원본을 보존하고 수동 PDF 추가를 안내합니다. 일부 글꼴은 내장 Noto로 대체하며 결과를 검토해야 합니다. 실제 Mac/Apple Silicon·Safari와 첫 1차 1교시 원본은 미검증입니다. PDF가 원본보다 커질 수 있으며 입력과 생성 PDF의 256MiB 한도를 넘으면 자료를 나누어야 합니다. 전체 백업은 등록한 문항·이미지·기록을 보관하지만 원본 PPTX·생성 PDF·분석 캐시는 포함하지 않습니다. PMRtest/NOAH는 수정하지 않았습니다.
