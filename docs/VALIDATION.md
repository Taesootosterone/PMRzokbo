### 실제 브라우저의 다섯 흐름

1. 문항 관리에서 **문제 PNG와 해설 PNG를 각각 업로드**하고 정답 ③·대단원·소단원·시험·2022년·35번·데모 표시·관련 개념을 저장했습니다. 단원에서 바로 풀고 ②를 제출해 오답 안내와 해설 이미지를 확인했습니다. 원본 확대, 별표, 메모 저장, 실제 클립보드의 고정 링크도 확인했습니다.
2. 최근 오답 목록에서 다시 풀어 ③을 제출했습니다. 최근 오답에서는 제외되고 이전 오답·다음 정답 **두 기록이 모두 남는 것**을 UI와 API로 확인했습니다.
3. 두 문항으로 시험을 만들고 ② 답 선택·다음 문항 이동 후 **실제 페이지를 닫았습니다**. 새 페이지로 다시 열어 위치와 ② 답을 확인하고 이전 문항으로 돌아가 ③으로 바꿨습니다. 나머지 ① 선택 후 최종 제출해 **2/2 정답**, 이전 문항 탐색·해설 확인을 검증했습니다. 제출 전 세션 API에 정답과 해설 이미지가 없는 것도 확인했습니다.
4. 같은 개념에 이미지형과 직접 입력형 문항을 연결했습니다. 개념 화면·버전 1 API에서 **두 문항**을 확인하고 외부 노트를 새 창으로 열었습니다. **외부 노트는 브라우저에서 응답을 주입한 데모 페이지**이며 실제 NOAH가 아닙니다. 등록한 UUID와 `#note/UUID` URL 전달을 확인했습니다.
5. 실제 실행 중인 DB에서 전체 백업을 만들고 **다른 디렉터리로 복원한 두 번째 서버(14311)**를 실행했습니다. 문항 수, 문제·해설 이미지의 **바이트 일치**, 전체 풀이 기록, 완료 시험 채점, 별표, 메모, 개념 ID 연결을 비교하고 복원된 화면을 열었습니다. 첫 서버(14310)는 별도 데이터로 동작했습니다.

추가로 브라우저에서 JSON 내보내기→동일 JSON 가져오기(기존 2개 유지), 수동 문항 수정, `2022년 직접 만든 데모 35번` 검색, 다른 Origin의 쓰기 거부를 확인했습니다. iPad 가로 1180×820, iPhone 세로 390×844에서 가로 넘침이 없는지 확인하고 iPhone 크기에서 답 선택·제출·해설 확인을 실제 실행했습니다. 네이티브 Safari를 실행한 것은 아닙니다.

## 설정에서 원버튼 전체 백업 — 2026-11-10

오른쪽 위 톱니바퀴의 **설정 → 전체 백업 다운로드**를 추가했습니다. 기존 CLI와 동일한 `pmrzokbo-full-backup` v1 `.pmrz` 형식으로 생성하며 DB 스키마와 사용자 데이터 위치는 변경하지 않았습니다. 파일은 버튼을 누른 브라우저의 다운로드 위치로 전달합니다. 파일명 날짜는 한국 시간(KST)입니다.

- 프로덕션 빌드·TypeScript 검사 통과.
- 데이터 계층·CLI 테스트 5개 통과, 실패/건너뜀 0.
- 브라우저 테스트 **2개 통과**, 실패/건너뜀 0. 기존 다섯 흐름을 다시 실행했고 전체 백업 단계는 CLI 함수 호출 대신 **실제 톱니바퀴 → 다운로드 버튼 → 브라우저 다운로드 파일**로 검증했습니다.
- 내려받은 파일의 형식·버전·DB/이미지 포함 여부를 검사하고 별도 경로와 두 번째 서버에서 복원했습니다. 이미지 원본 바이트, 전체 시도 기록, 완료 시험, 별표, 메모, 개념 연결이 일치했습니다.
- 별도 브라우저 테스트에서 백업 실패 응답을 주입해 오류 표시, 진행 중 버튼/닫기 비활성화, 실패 후 재시도 및 실제 다운로드를 확인했습니다. 빈 문항 은행도 백업 가능하며 다른 Origin의 요청과 GET 다운로드는 거부합니다.
- iPhone 크기에서 톱니바퀴와 설정 버튼 접근, 가로 넘침 없음, Escape 닫기와 버튼 포커스 복귀를 확인했습니다.
- 임시 백업 파일은 서버의 전용 임시 디렉터리에서 생성하고 다운로드 응답 준비 후 정리합니다. 코드·`.env.local`·실행 잠금은 전체 백업에 포함하지 않습니다. 복원은 기존의 앱 중지 후 CLI 절차를 사용합니다.

실제 Safari/macOS 다운로드와 초대용량 백업은 미검증입니다. Linux Chromium에서 실제 내려받기와 복원까지 확인한 결과입니다. PMRtest/NOAH는 변경하지 않았고 게시도 하지 않았습니다.

## GitHub 자동 다운로드·수동 적용 — 2026-11-11

v1.1.0에 **설정 → 앱 업데이트**를 추가했습니다. 앱 시작 시와 기본 6시간 간격으로 확인·다운로드만 수행하고, 적용 버튼을 눌러야 의존성 설치·빌드·전체 백업·서버 교체를 진행합니다. 원래 코드 폴더·로컬 변경·`.env.local`·사용자 데이터는 덮어쓰지 않습니다. 자동 간격의 실제 6시간 경과는 대기하지 않았고 시작 시 자동 동작과 설정값 검사를 검증했습니다.

- 빌드와 TypeScript 검사 통과. 데이터/CLI/업데이트 테스트 **8개 통과**, 브라우저 통합 테스트 **3개 통과**. 실패/건너뜀 0.
- 실제 GitHub `Taesootosterone/PMRzokbo`의 읽기 명령은 성공했으나 원격 커밋/main이 없는 것을 확인했습니다. 원격에 초기 코드를 업로드하지 않았습니다.
- 업데이트 검증용으로 별도의 Git 저장소와 main 커밋을 만들었습니다. 테스트 프로세스의 Git URL 매핑으로만 해당 저장소를 연결했으며, 제품 코드에 테스트 원본 주소나 인증 우회 경로를 추가하지 않았습니다.
- **자동 다운로드**: 별도 실제 서버(14312)를 자동 확인 활성 상태로 시작해 새 커밋이 다운로드된 것을 확인했습니다. 현재 서버 버전은 그대로이며 새 코드의 `node_modules`와 활성 포인터가 만들어지지 않아 적용/실행되지 않았음을 확인했습니다.
- **버튼 적용**: Chromium에서 설정의 업데이트 확인·다운로드 → 적용을 눌렀습니다. 실제 `npm ci`, Next 프로덕션 빌드, 적용 전 `.pmrz` 백업, 서버 중지와 새 supervisor/서버 시작, 버전/커밋 health 응답, 브라우저 새로고침을 확인했습니다.
