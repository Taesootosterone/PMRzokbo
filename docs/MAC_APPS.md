# 리햅 Mac 앱 — v1.2.0

## 기존 사용자가 처음 적용하기

1. 기존 웹 화면에서 **톱니바퀴 → 앱 업데이트 → 업데이트 확인·다운로드 → 업데이트 적용**을 실행합니다. v1.1의 원래 실행 폴더를 새로 덮어쓸 필요가 없습니다. 새 릴리스의 supervisor가 Mac 앱을 자동으로 설치합니다.
2. Finder의 **이동 → 홈 → Applications**에 아래 앱이 생겼는지 확인합니다. 생성되지 않았다면 웹 설정의 **Mac 앱 설치/복구**에서 오류를 확인하거나 다시 시도합니다. 원본 폴더가 ZIP으로 설치되어 `.git`이 없어도 지원합니다.
3. 기존 터미널에 종속된 서버를 바꾸려면 **리햅 중지 → 리햅 열기**를 한 번 실행합니다. 이미 켜진 서버에 ‘열기’를 실행하는 것만으로는 실행 방식이 바뀌지 않습니다.

| 앱 | 더블클릭했을 때 |
| --- | --- |
| `~/Applications/리햅 열기.app` | 서버가 없으면 백그라운드 시작, 있으면 재사용 후 로컬 브라우저 열기 |
| `~/Applications/리햅 업데이트.app` | 필요 시 서버 시작 → 최신 main 확인·다운로드 → 설치·빌드 → 전체 백업 → 재시작·실행 확인 → 결과 대화상자 |
| `~/Applications/리햅 중지.app` | 이 설치와 데이터 경로에 해당하는 서버만 정상 종료 |
| `~/Applications/리햅 상태.app` | 실행 여부·버전·로컬 주소·데이터 위치 표시 |

업데이트 전에 편집 중인 문항·메모를 저장하세요. 시작 알림 후 완료 대화상자가 나올 때까지 기다립니다. 이미지가 많거나 네트워크가 느리면 시간이 걸립니다. 최신 버전이면 설치 없이 알려줍니다. 앱 중복 실행은 제어 잠금으로 막고, 웹에서 업데이트 중이면 완료를 기다립니다. 업데이트 앱 자체는 적용 의사를 나타내므로 별도 적용 버튼을 요구하지 않습니다. 앱을 실행하지 않았을 때 자동 확인은 기존처럼 **다운로드까지만** 합니다.

## 최신 소스에서 처음 설치하기

Node.js **24**, Git, macOS의 `/usr/bin/osacompile`·`/usr/bin/open`을 사용합니다. 추가 런처 프레임워크는 필요 없습니다. Node는 설치 시 절대 경로를 기억하므로 Finder의 PATH에 Node가 없어도 동작합니다. NVM을 사용하면서 시스템 Node가 26이어도 최초 설정 스크립트가 설치된 NVM의 **24**를 찾습니다.

```sh
cd "$HOME/Projects/PMRzokbo"
# nvm 사용자라면 먼저 nvm use 24
npm run mac:setup
```

또는 Finder에서 `mac/처음설정.command`를 더블클릭하세요. 의존성·프로덕션 빌드가 없으면 준비한 뒤 앱 네 개를 설치합니다. 설치 명령은 서버를 임의 종료하지 않습니다. 새 서버 실행은 ‘리햅 열기’를 사용합니다. Node 24나 코드 폴더를 옮기거나 삭제하면 앱이 실행되지 않을 수 있습니다. 새 Node/경로에서 설정을 다시 확인하세요. 다른 설치의 설정을 자동 덮어쓰지는 않습니다.

CLI도 제공합니다: `npm run mac:open`, `mac:update`, `mac:stop`, `mac:status`. `npm run mac:setup`은 실제 macOS 전용입니다.

## 보존되는 설정과 파일

| 위치 | 내용 |
| --- | --- |
| `~/.config/pmrzokbo/mac.json` | 형식 `pmrzokbo-mac-control` v1, 원래 설치 폴더·Node 경로·데이터·호스트·포트·업데이트 원본·인스턴스 식별자 |
| `~/.config/pmrzokbo/control.mjs` | 활성 릴리스를 찾아 제어 모듈을 여는 독립 실행기 |
| `~/.config/pmrzokbo/control.lock` | 제어 동작의 PID·임의 식별자, 완료 시 정리·죽은 PID만 회수 |
| `~/Applications/리햅 *.app/Contents/Resources/pmrzokbo-control-app.json` | 리햅 소유 표식, 설치 경로·동작·런처 개정·Node 경로 |
| `<데이터>/desktop/logs/server.log` | 앱으로 백그라운드 실행한 서버의 표준 출력·오류 |
| `<데이터>/updates/backups/before-update-*.pmrz` | 적용 직전 DB·이미지 전체 백업 |

사용자 데이터의 기본 위치는 계속 **`~/Library/Application Support/PMRZokbo`**입니다. 사용자 지정 데이터 경로도 그대로 보존합니다. Mac 제어 설정·앱·로그·업데이트 코드는 전체 데이터 백업에 포함되지 않습니다. 새 Mac에서는 앱을 새로 설치하고 전체 `.pmrz`를 복원하세요. 앱을 삭제해도 DB·이미지·풀이 기록은 삭제하지 않습니다.

현재 프로덕션 서버의 유효 호스트·포트·데이터 설정을 자동 설치 시 기억합니다. 수동 재설치 시 `.env.local`과 환경 변수, 같은 설치의 기존 Mac 설정을 차례로 사용합니다. 서버 주소를 바꾸려면 `.env.local` 변경 후 기존 서버를 중지하고 **터미널의 `npm start`로 새 설정을 한 번 실행**하거나, Node 24에서 새 환경 값을 지정해 `npm run mac:setup`을 실행하세요. 다시 자동 등록된 앱은 변경한 설정을 사용합니다. 앱 안에 비밀 값·업데이터 인증 토큰을 저장하지 않습니다.

Tailscale로 접속하려면 맥미니의 `PMRZ_HOST=0.0.0.0` 설정과 Tailscale 실행이 필요합니다. 맥미니의 현재 Tailscale IPv4가 `100.101.153.53`이고 포트가 기본값이라면 다른 기기에서는 **`http://100.101.153.53:4310`**, 맥미니 자체에서는 **`http://127.0.0.1:4310`**입니다. IP/포트 변경 시 실제 값으로 바꾸세요. **Mac 앱은 설치된 Mac의 로컬 서버를 제어합니다.** 맥북에서 실행한 업데이트 앱으로 맥미니 서버를 원격 업데이트하는 기능은 없습니다. 맥미니에서 이 앱을 실행하거나 맥미니 웹 설정의 업데이트 버튼을 사용하세요.

## 실패와 복구 범위

- 다운로드·설치·빌드 실패 시 기존 실행본을 유지합니다. 새 버전 실행 확인 실패 시 기존 코드로 돌아갑니다. 사용자 데이터를 이전 백업으로 자동 덮어쓰지 않습니다. 상세 동작은 [GitHub 업데이트 안내](UPDATES.md)를 참고하세요.
- 포트에 다른 서비스나 다른 데이터 경로의 리햅이 있으면 제어를 거부합니다. 설치 경로·데이터 경로에서 만든 인스턴스 식별자를 health 응답으로 비교하며 다른 앱의 PID나 포트를 강제 종료하지 않습니다. 옛 v1.1 서버는 식별자를 제공하지 않으므로 웹에서 먼저 업데이트하거나 기존 터미널 서버를 중지하세요.
- 같은 이름의 다른 앱, 다른 설치의 Mac 설정, 설정 심볼릭 링크는 덮어쓰지 않습니다. 네 앱을 먼저 임시 폴더에서 컴파일한 뒤 소유 표식을 확인해 교체합니다. 컴파일 실패 시 기존 앱을 유지하고 교체 실패 시 복구를 시도합니다.
- macOS 기본 도구로 해당 Mac에서 앱을 생성하며 Apple 공증 배포본이 아닙니다. macOS가 실행 확인을 요구하면 Finder의 ‘열기’ 안내를 따르세요. 보안 설정 전체를 끄는 절차는 필요하지 않습니다.
- 로그인 자동 시작·LaunchAgent·절전 방지·Mac 원격 전원 켜기는 이번 버전에 포함하지 않습니다. 브라우저를 닫아도 서버는 유지되지만 Mac 재부팅 뒤에는 ‘리햅 열기’를 다시 실행합니다.
