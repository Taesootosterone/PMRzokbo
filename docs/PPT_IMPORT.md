# PPTX 자동 가져오기 — v1.4.0

**PPTX만 올리면 앱이 PDF를 자동 생성해 저장하고, 그 PDF로 문항 분석을 이어갑니다.** PowerPoint·Keynote·LibreOffice 설치나 PDF 준비가 필요 없습니다. 자료와 OCR은 서버 Mac 안에서 처리하며 외부 문서 변환 서비스로 보내지 않습니다.

## 사용 순서

1. **리햅 업데이트.app** 또는 웹 설정에서 v1.4.0 이상으로 업데이트합니다.
2. **문항 관리 → PPTX 자동 가져오기 → PPTX 파일 올리기**를 누릅니다. 이미지 속 글자도 읽어야 하면 OCR을 켭니다.
3. **슬라이드 구조 읽는 중 → 앱 내부에서 PDF 만드는 중 → 슬라이드 화면 변환/OCR → 검토 대기** 순서로 진행합니다. 전송이 끝나면 브라우저를 닫아도 서버가 켜져 있는 동안 작업은 계속됩니다.
4. **PDF 자동 생성·저장 완료**가 나타나면 **PDF 열어보기 / PDF 다운로드**로 결과를 확인하거나 저장할 수 있습니다. 후속 분석이 끝나기 전에도 완성된 PDF를 열 수 있습니다.
5. 문제/정답·해설 슬라이드 범위, 정답 번호, 대단원·소단원, 연도·시험 종류·원래 번호, 관련 개념을 확인·수정합니다. 이미지를 누르면 확대됩니다.
6. 중간에 멈출 때는 **검토 초안 저장**을 누릅니다. 다시 접속해 같은 PPT를 선택하면 저장한 수정 내용을 이어서 검토할 수 있습니다.
7. 등록할 문항을 선택하고 **선택한 문항의 슬라이드 묶음·정답·분류를 확인했습니다**를 체크해 등록합니다. 직접 만든 예시 자료에만 데모 문항 표시를 켭니다.
8. 문항 관리에서 **이 문제 풀기 → 답 선택 → 제출 → 해설 확인**으로 확인합니다.

[PDF 자동 생성 후 검토 화면](screenshots/ppt-native-ready.png)

자동 결과는 초안입니다. 의료적 정답을 새로 푸는 기능은 아니며 원본의 정답 표시를 읽습니다. 원본과 변환 결과, 문항 범위를 대조하세요.

## 이전 자료와 재분석

PDF를 기다리던 자료나 기존 방식으로 처리한 자료는 해당 PPT를 선택하고 **보존한 PPT로 PDF 자동 생성**을 누르세요. 원본을 다시 올릴 필요가 없습니다. 재분석은 수정한 검토 초안을 초기화하므로 안내가 나타납니다. 등록한 문항·이미지·풀이 기록은 덮어쓰지 않습니다.

**보존한 원본 다시 분석**은 선택했던 방식을 유지합니다. 이전 버전처럼 방식 정보가 없는 작업은 내장 PDF 생성으로 진행합니다.

## 문항마다 장수가 다른 파일

고정된 3장 단위로 자르지 않고 번호와 역할 제목을 읽습니다. 같은 번호 아래 **문제 / 정답 / 복원 답·이견 / 워드 원문 해설 / 근거 대조**가 반복되는 형식을 지원합니다. 해설 뒤의 **문제 지문·보기 확대 / 문제 그림 확대**도 문제 자료로 모읍니다.

예를 들어 문제 `78,86-93`, 정답·해설 `79-85,94`처럼 연속되지 않는 범위도 가능합니다. 여러 장은 문제 이미지와 해설 이미지 각각에 세로로 이어 붙입니다. 답안 페이지가 문제 범위에 들어가지 않았는지도 확인하세요.

**문항 묶음·시험 정보 조정**에서 자동, 문항 시작 슬라이드 직접 지정(`2,6,9,14`), 장수가 일정한 자료의 반복 패턴을 선택할 수 있습니다. 전체 슬라이드 보기에서도 문항 시작을 표시할 수 있습니다. 묶음을 다시 만들면 개별 초안 수정이 초기화됩니다. 연도·시험 종류만 고치려면 **연도·시험 종류만 전체에 적용**을 사용하세요.

개별 범위는 `2,3`, `2-3`, `4-7`로 입력하며, 문제와 해설 범위는 각각 필요하고 서로 겹치면 등록되지 않습니다.

## 정답·분류·노트

`정답: ③`, `답) 3번`, `Answer: 2`와 정답 슬라이드의 실제 선지 형광펜을 읽습니다. 문제에도 있는 같은 강조나 일반 글자색만으로 답을 고르지 않습니다. 여러 답·복수 강조·**복원 답·이견**이 있으면 정답을 비워 두며, 직접 지정해야 등록할 수 있습니다.

원본 머리글에 대단원이 있으면 그 이름을 유지합니다. 소단원과 개념은 용어 규칙으로 추천하고 근거·다른 후보를 보여 줍니다. 단서가 없으면 확인 필요로 남깁니다. OCR은 숫자·동그라미·약어를 잘못 읽을 수 있으며 낮은 신뢰도의 결과는 자동 정답·분류에 쓰지 않습니다.

정답·해설의 발표자노트는 문항 해설 텍스트로 보존합니다. 추출한 글자·노트는 검토 화면의 자세히 보기에서도 확인할 수 있습니다.

## 내장 변환의 지원 범위

한글·영문 글상자, 형광펜·글자색, 일반 도형, PNG/JPEG 등의 삽입 이미지와 기본 표를 지원합니다. 원래 순서와 사진 비율·자르기 정보를 읽으며 내장 Noto Sans KR 글꼴을 사용합니다. 다른 글꼴은 대체 사실을 표시합니다.

**생성 PDF는 슬라이드 이미지 기반 PDF**입니다. PDF 자체의 검색 가능한 텍스트는 없지만 앱은 원본 PPTX의 글자·노트를 별도로 읽어 검색·분류에 사용합니다. 모든 PowerPoint 기능·글꼴·레이아웃을 똑같이 재현하는 변환기는 아닙니다.

차트·SmartArt·수식·OLE 개체·동영상·일부 그룹 도형/병합 표 등은 아직 내장 변환 대상이 아닙니다. 지원하지 않는 항목은 해당 장을 알려 주고 멈추며 불완전한 PDF를 성공한 것처럼 등록하지 않습니다. 원본은 보존합니다.

이때 **같은 PPT에서 저장한 PDF로 계속하기**로 PDF를 추가할 수 있습니다. 새 업로드의 **다른 가져오기 방식 → 이미 만든 PDF를 함께 올리기**도 가능합니다. 기존 LibreOffice가 설치돼 있다면 그 방식도 선택할 수 있지만 기본값은 내장 자동 생성입니다.

수동 PDF는 **슬라이드 한 장 = PDF 한 페이지**, 같은 순서, 숨김 슬라이드 포함으로 저장하세요. PowerPoint에서는 파일 → 내보내기/다른 이름으로 저장 → PDF, Keynote에서는 파일 → 다음으로 내보내기 → PDF를 사용합니다. 모아찍기·노트 페이지·단계별 빌드는 제외합니다. 앱은 장수를 비교하지만 같은 장수의 다른 파일이나 바뀐 순서까지 자동 판별하지는 못하므로 미리보기를 대조해야 합니다.

## 크기·저장·백업

입력 PPTX는 **256MiB·1,200장**, 수동 추가 PDF는 256MiB까지 받습니다. 구형 `.ppt`는 `.pptx`로 저장해 주세요. 생성 PDF도 256MiB까지 처리하며 이미지 기반이라 원본보다 커질 수 있습니다. 한도를 넘으면 문항 경계에서 PPT를 나누어 가져오세요.

자료는 코드 밖의 `<데이터 경로>/ppt-imports/<분석 ID>/`에 보관합니다. 자동 생성 PDF는 **`native/source.pdf`**입니다. Mac 기본 데이터 경로는 `~/Library/Application Support/PMRZokbo`입니다. 앱 종료·재시작·코드 업데이트로 저장한 PDF를 지우지 않습니다. 중단된 작업은 원본에서 재분석할 수 있습니다. 분석 중 서버 종료·업데이트는 피하세요.

**분석 파일 삭제**는 원본 사본·자동 생성 PDF·미리보기·초안을 삭제합니다. 등록한 문항·이미지·기록은 유지합니다. PDF를 따로 보관하려면 먼저 다운로드하세요.

등록한 문항·문제/해설 이미지·출처·개념 연결은 콘텐츠 JSON과 전체 `.pmrz` 백업에 포함됩니다. 기록·별표·메모·진행 시험은 전체 백업에 포함됩니다. **원본 PPTX·생성/추가 PDF·미등록 초안·캐시는 전체 백업에 포함하지 않으므로 원본과 필요한 PDF는 따로 보관하세요.**

## 중복·연동

같은 PPTX 원본 파일의 같은 문제 범위에서 안정적인 문항 ID를 만듭니다. 재등록하면 기존 수정·시도 기록·별표·메모를 유지합니다. PDF를 다시 생성하는 것만으로 ID를 바꾸지 않습니다. 원본을 수정해 저장하거나 문제 범위를 바꾸면 새 ID가 될 수 있으니 기존 목록을 확인하세요.

등록한 내용을 고칠 때는 **문항 관리 → 문항 수정**을 사용하세요. 재가져오기로 기존 정답·이미지를 자동 교체하지 않습니다. 개념은 같은 이름의 기존 개념을 재사용하고 NOAH 노트 ID·URL은 유지합니다. NOAH 본문이나 DB는 변경하지 않습니다.

## 검증

실제 2차 1교시 원본(31,380,050바이트·376장·63문항)을 PPTX만 업로드해 PDF 생성·저장·다운로드와 후속 분석을 확인했습니다. 정답 표기 52개를 읽고 11개를 수동 확인 대상으로 남겼습니다. 의료적 정답 정확도를 평가한 비율은 아닙니다.

세부 검사와 실제 macOS 미검증 범위는 [검증 기록](VALIDATION.md)을 참고하세요. 첫 1차 1교시 파일은 채팅 전송 한도로 열지 못했으며 그 파일의 형식·인식률은 아직 확인하지 못했습니다.
