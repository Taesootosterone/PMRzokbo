# PPTX 자동 가져오기 — v1.3.1

문항마다 장수가 다른 **문제 → 정답 → 해설** PPTX를 가져옵니다. 고정된 3장 단위로 자르지 않고 문항 번호와 정답·해설 표시로 경계를 찾습니다. 원래 화면을 이미지로 보존하며, 이미지 속 글자는 로컬 OCR로 읽을 수 있습니다. 자동 결과는 **초안**이며 사용자가 확인한 문항만 등록합니다.

## 처음 한 번 준비

1. 리햅 업데이트.app 또는 웹 설정의 업데이트로 v1.3.1 이상을 적용합니다.
2. **서버를 실행하는 맥미니**에 [무료 LibreOffice](https://www.libreoffice.org/download/download-libreoffice/)를 설치합니다. Mac용 설치 파일을 열어 LibreOffice.app을 **Applications**에 넣고 앱을 한 번 열어 macOS의 실행 확인을 마칩니다. PPT 화면을 PDF·이미지로 변환하는 데 사용합니다.
3. 웹에서 **문항 관리 → PPTX 자동 가져오기**로 이동합니다. 설치가 확인되지 않으면 이 화면을 새로고침합니다.

PowerPoint 유료 라이선스나 외부 AI API 키는 필요 없습니다. OCR 프로그램과 한국어·영어 모델은 앱의 npm 의존성으로 설치됩니다. OCR·단원 추천은 서버 Mac에서 실행하며 외부 AI API로 PPT를 보내지 않습니다.

표준 설치 경로는 `/Applications/LibreOffice.app/Contents/MacOS/soffice`입니다. 다른 경로라면 서버 환경 변수 `PMRZ_LIBREOFFICE_BIN`에 **실제 실행 파일의 절대 경로**를 지정합니다. 이 설정은 개인 실행 설정이며 GitHub에 올릴 필요가 없습니다.

## 가져오기 순서

1. **PPTX 파일 올리기**에서 파일을 선택합니다. `.pptx`만 지원하며 파일당 **256MB·1,200장**까지 처리합니다. `.ppt`는 PowerPoint에서 `.pptx`로 저장합니다. 큰 파일은 문항 경계에서 여러 파일로 나누세요.
2. 스캔 이미지가 섞여 있다면 **이미지 속 글자도 OCR로 읽기**를 켭니다. 업로드 후 구조 읽기 → 화면 변환 → 필요한 슬라이드의 OCR → 검토 대기 순서로 진행합니다.
3. 슬라이드의 순서·글자·발표자 노트를 읽고 문항별 문제/정답·해설 범위를 제안합니다. 표지는 제외될 수 있으므로 제외 안내도 확인합니다. 정답은 `정답: ③`, `Answer: 2` 등의 표시에서 읽으며, 내용 자체를 풀어 정답을 만들어내지는 않습니다.
4. 각 문항의 **문제 슬라이드 / 정답·해설 슬라이드 / 정답 번호 / 대단원 / 소단원 / 연도 / 시험 종류 / 원래 번호 / 관련 개념**을 확인·수정합니다. 이미지는 클릭해 확대할 수 있습니다.
5. 중간에 멈출 때는 **검토 초안 저장**을 누릅니다. 수정한 범위·정답·분류가 서버에 저장되어 창을 다시 열고 해당 PPT를 선택하면 이어서 검토할 수 있습니다. 등록할 문항을 선택하고 **선택한 문항의 슬라이드 묶음·정답·분류를 확인했습니다**를 체크한 뒤 등록합니다. 직접 만든 예시 파일에만 데모 문항 표시를 켭니다.
6. 문항 관리에서 새 문항을 열어 **이 문제 풀기 → 답 선택 → 제출 → 해설 확인**으로 최종 확인합니다.

예를 들어 2–3장이 문제, 4–5장이 정답·해설인 문항과 6장이 문제, 7장이 정답·해설인 문항을 각각 하나의 문항으로 등록할 수 있습니다. 한 문항의 여러 장은 세로로 이어 붙인 문제 이미지와 해설 이미지가 됩니다.

## 번호·역할 머리글이 반복되는 파일

v1.3.1은 각 장에 같은 문항 번호가 반복되고 그 아래에 **문제 / 정답 / 복원 답·이견 / 워드 원문 해설 / 근거 대조**가 붙는 형식을 읽습니다. **문제 지문·보기 확대 / 문제 그림 확대**가 해설 뒤에 있어도 해당 문항의 문제 자료에 포함합니다. 예를 들어 문제 범위가 `78,86-93`, 해설 범위가 `79-85,94`처럼 연속되지 않을 수 있습니다.

정답 슬라이드에서 선지에 적용된 실제 형광펜 표시도 정답 근거로 읽습니다. 일반 글자색이나 도형색으로 추측하지 않으며 문제 슬라이드에도 같은 표시가 있으면 정답 근거로 쓰지 않습니다. 표시가 여러 개이거나 텍스트 정답과 다르거나 **복원 답·이견**이 있으면 정답을 비워 두므로 직접 확인·지정하세요. `답) 3번` 표기도 지원합니다.

시험 머리글에 대단원이 있으면 원본의 대단원 이름을 유지하고, 해당 영역 안에서 소단원과 개념을 추천합니다. 소단원 단서가 부족하면 확인 필요로 표시합니다. 의료 내용의 정오를 새로 판단하는 기능은 아닙니다.

v1.3.0에서 분석했던 원본은 **보존한 원본 다시 분석**을 누르면 새 규칙이 적용됩니다. 이미 등록한 문항은 자동으로 수정하지 않습니다. 문제 범위를 바꾸면 문항 ID가 달라질 수 있으니 기존 문항도 확인하세요.

## 자동 경계를 고칠 때

**문항 묶음·시험 정보 조정**을 열고 다음 중 하나를 사용합니다.

- **자동**: 문항 번호·정답·해설 표시를 다시 읽어 묶습니다. 같은 문항 번호가 이어지는 문제 슬라이드는 묶어서 다룹니다.
- **문항 시작 슬라이드 직접 지정**: 장수가 제각각이면 `2,6,9,14`처럼 **각 문제의 첫 장**을 입력합니다. 다음 문제 직전까지를 한 문항으로 묶습니다. 전체 슬라이드 보기에서 ‘문항 시작으로 표시’할 수도 있습니다.
- **반복 패턴**: 장수가 일정한 파일에만 시작 위치와 문제/정답/해설 장수를 지정합니다.

**이 설정으로 묶음 다시 만들기**는 현재 초안의 개별 수정 내용을 초기화하므로 먼저 경계를 고친 후 정답·분류를 수정하세요. 연도·시험 종류만 바꾸고 싶으면 **연도·시험 종류만 전체에 적용**을 사용합니다.

개별 문항의 범위는 `2,3`, `2-3`, `4-7` 형식으로 고칠 수 있습니다. 문제와 해설 범위는 각각 필요하며 서로 겹치면 등록할 수 없습니다. 문제 쪽에 정답 슬라이드가 들어가지 않았는지도 직접 확인하세요.

## 분류와 정답의 한계

- 대단원·소단원은 재활의학 **용어 규칙에 따른 추천**입니다. 매칭된 용어와 다른 후보를 보여 줍니다. 사용자만의 목차와 다르거나 단서가 없으면 직접 수정하세요. 단서를 못 찾으면 ‘미분류’로 표시합니다.
- 정답 표시가 없거나 서로 다른 답이 나오면 정답을 비워 둡니다. 정답이 없는 선택 문항은 등록되지 않습니다. 문항 안의 선지 번호만으로 정답을 고르지 않습니다.
- OCR은 숫자·동그라미·영문 약자·낮은 해상도에서 틀릴 수 있습니다. 신뢰도가 낮은 OCR은 자동 정답·분류에 사용하지 않고 표시합니다. 중요한 것은 원본 화면과의 대조입니다.
- 정답이 색상·도형 강조만으로 표시된 경우, 문항 번호가 없는 이미지, 한 슬라이드에 문제와 답이 함께 있는 경우, 복수 정답은 자동 처리가 어려워 범위/정답 수정을 해야 할 수 있습니다.
- 원본의 글꼴이 서버에 없으면 LibreOffice에서 대체될 수 있습니다. 애니메이션·동영상·외부 파일 참조는 정적인 문제 이미지와 다르게 동작하거나 지원하지 않을 수 있습니다. 원본 PPT도 보관하세요.

## 저장·중복·백업

원본 사본·변환 화면·OCR·분석 초안은 코드 밖의 `<데이터 경로>/ppt-imports/<분석 ID>/`에 남습니다. 앱 업데이트로 삭제하지 않습니다. 브라우저를 닫아도 서버가 켜져 있으면 분석이 계속됩니다. 분석 중에는 서버 종료·업데이트를 피하세요. 중단되었다면 **보존한 원본 다시 분석**을 사용할 수 있습니다.

정답·해설 슬라이드의 발표자노트는 문항의 해설 텍스트로 함께 보존하며, 추출한 글자 보기에서도 확인할 수 있습니다. 수정 중인 검토 초안은 ‘검토 초안 저장’을 눌러야 다음 접속 때 복원됩니다.

같은 원본 파일의 같은 문제 슬라이드에서 안정적인 문항 ID를 만들고 재등록 시 기존 문항을 유지합니다. 사용자 수정·풀이 기록·별표·메모를 덮어쓰지 않습니다. 원본을 수정해 새로 저장하면 파일 해시가 달라져 새 문항으로 처리될 수 있습니다. 슬라이드 범위를 바꾸는 것도 새 문항으로 이어질 수 있으니 기존 목록을 확인하세요.

이미 등록한 문항의 정답·분류·해설을 바꾸려면 **문항 관리 → 문항 수정**을 사용하세요. 같은 PPT를 다시 등록해 기존 내용을 덮어쓰는 방식은 지원하지 않습니다.

관련 개념은 이름이 같은 기존 개념을 재사용합니다. 기존 NOAH 노트 ID·URL은 변경하지 않습니다. 없는 개념만 새로 만들며 실제 NOAH 본문이나 DB에 접근하지 않습니다.

등록된 문항·문제/해설 이미지·출처 정보·개념 연결은 기존 전체 `.pmrz` 백업과 콘텐츠 JSON에 포함됩니다. 풀이 기록은 기존처럼 전체 `.pmrz` 백업에만 포함됩니다. **원본 PPT·미등록 초안·OCR 캐시·변환 PDF는 전체 백업에 포함하지 않으니 원본을 별도 보관하세요.**

**분석 파일 삭제**는 원본 사본·슬라이드 미리보기·초안만 삭제합니다. 이미 등록한 문제은행 문항·이미지·기록은 유지합니다. 분석 원본을 지워도 등록한 문항은 풀 수 있습니다.

## 구현·검증 범위

PPTX 순서·텍스트·노트는 OOXML에서 읽고, LibreOffice → PDF → PNG로 화면을 보존합니다. 한국어·영어 OCR은 Tesseract.js로 로컬 실행합니다. 단원 추천은 `lib/ppt-model.mjs`에 분리해 향후 다른 분류기로 교체할 수 있습니다. DB 스키마와 실행 프로토콜은 1을 유지하며 기존 데이터에 새 DB를 덮어쓰지 않습니다.

처음 첨부된 1차 1교시 원본은 **채팅 파일 전송의 32MiB 제한**으로 내려받지 못했습니다. 이후 첨부된 **2차 1교시 원본(31,380,050바이트)**은 실제로 열어 376장·63문항의 구조와 전체 화면 변환을 확인했습니다. 정답 표기를 읽은 초안 52개와 수동 확인이 필요한 11개로 구분했으며, 이는 의료적 정답 정확도를 평가한 수치가 아닙니다. 별도 테스트 데이터에서 일부 문항의 등록·풀이·백업 복원을 검증했습니다. 앱의 256MB 업로드 제한은 채팅 전송 제한과 별개입니다. 결과와 실제 macOS 미검증 범위는 [검증 기록](VALIDATION.md)을 참고하세요.
